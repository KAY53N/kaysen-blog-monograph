LAND 的全称是 Local Area Network Denial，大约出现在 1997 年，对应 [CVE-1999-0016](https://nvd.nist.gov/vuln/detail/CVE-1999-0016)。它不依赖复杂的漏洞代码，靠的是当时 TCP/IP 协议栈的一个疏忽：源 IP 和目的 IP 相同、并且带 SYN 标志的包，主机仍按正常流程处理，等于自己跟自己做三次握手。实现差的系统会在这个过程里空转，CPU 被占满，严重时死机或重启。

这类笔记一般写两块：攻击本身是怎么回事，以及为什么总提到 hping。下面按这个结构写，顺手改几处现在还在流传、其实已经过时的说法。先说清楚：**这不是攻击教程。** 对别人的系统发伪造包，在大多数地方都违法。本文只讲原理、历史和防护，不会给出发包命令。

## 0x00 攻击原理

典型的 LAND 包特征很简单：

| 字段 | 内容 |
| --- | --- |
| IP 源地址 | 和目的地址相同 |
| IP 目的地址 | 目标主机的地址 |
| TCP 标志 | 必须带 SYN |
| TCP 端口 | 早期样本里，源端口和目的端口也经常写成同一个 |

三次握手的前提是：对面是另一台机器。主机收到 SYN 之后，会分配连接控制块，回一个 SYN-ACK，然后等 ACK。如果这个 SYN 的源地址就是自己，发出去的 SYN-ACK 会被本机再次收到。早期实现里没有「源地址等于目的地址就丢包」这一步，协议栈就会在本机反复处理、反复响应，CPU 全耗在握手上。

这和把带宽灌满的洪水攻击不是一类事。LAND 打的是协议栈，不是网线。

所以 LAND 要奏效，下面三件事得同时成立：伪造包能送到目标；目标协议栈会接受「源地址是自己」的 SYN；路上的防火墙或 martian 检查没有把它丢掉。现在这三环里，通常至少有一环已经拦住了。

另外还有一种很常见的说法：「Windows XP SP2、Windows Server 2003，还有 Sun、BSD、Mac，防得都很差，因为它们用的都是 BSD 协议栈。」这话不准确。Windows 的 TCP/IP 是自己写的，并不是 BSD 那一套；Solaris 也不是把 BSD 网络代码复制过去。1997 年前后，好几家协议栈都漏了同一类检查，这是相同的设计疏忽在不同代码里各犯一次，不是因为它们同源。至于 XP SP2 和 2003，那是二十年前实验报告里的结论，不能拿到现在当事实。补丁、默认防火墙和内核校验都补上之后，经典的 LAND 在现在的桌面和服务器上基本已经失效。

## 0x01 关于 hping3

[hping](http://www.hping.org/) 是 Salvatore Sanfilippo 写的开源工具，用来构造和解析 TCP/IP 包。目前常用的是 hping3，可以用 Tcl 写脚本调用它的接口。安全审计、测防火墙、看设备怎么处理畸形包，都会用到它。它的长处是包头里每一段几乎都能指定，不必只发「正常」流量。

中文说明可以看 [hping3 命令](http://man.linuxde.net/hping3)，更完整的内容在上游文档。hping 能拼出符合 LAND 特征的包，只说明这个工具够底层，不等于该拿去打生产环境。把发包速率拉满、伪造源地址、对着公网或别人的机器发 SYN，这些步骤不该出现在博客里。

如果你在**自己的隔离环境**里做协议栈或防火墙回归，要看的是拦截有没有生效，不是机器会不会挂：

1. 源地址和目的地址相同的 SYN，有没有在进入套接字之前被丢掉。
2. 丢掉之后，CPU、连接表、日志有没有明显异常。
3. 边界设备有没有把这类包记成伪造或 martian，而不是放进业务端口。

审计里更合理的做法是：包量可控，能随时停。把实验改成洪水，或者换成别人的地址，已经超出这篇文章该写的范围。

## 现在还要防什么

对现在的内核来说，经典 LAND 基本是道历史题。它留下来的几条检查，倒还在用：

- **非法组合直接丢。** 源地址是本机、源地址是广播或组播、明显不可路由的 martian，应该在协议栈或主机防火墙丢掉，不要交给 TCP 状态机接着处理。
- **防源地址伪造。** 出口做 uRPF / 反向路径过滤；入口不要接受「声称来自你自己网段、却从外面进来」的包。LAND 只是源地址伪造里最简单的一种。
- **少暴露端口。** 没必要对全网开放的端口就不要开。连接表上限、SYN cookies、conntrack 限制，防的是更常见的握手滥用，不只是 LAND。
- **把这类包写进回归。** 换网卡、加网络命名空间、加 eBPF 路径之后，都有可能让本该丢掉的包重新进协议栈。回归里保留一条：源地址等于目的地址的 SYN 必须被丢掉，而且处理过程不该把 CPU 拖死。

1997 年那个具体样本不重要。重要的是：协议栈不该尽力理解每一张包，不该处理的包就该拒绝。LAND 当时能打挂系统，是因为少了这层检查。
